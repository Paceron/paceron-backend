Demo con base local

Cómo usar la base de Docker durante la demo y volver a dejarla como está ahora.

La idea en una línea: antes de empezar se congela la base como baseline. Entre rondas, un comando la vuelve a esa foto en 3 segundos. Al terminar, otro la deja limpia de verdad.

Nada de esto toca Supabase. Todo pasa en el Postgres del Docker de tu máquina.

Todos los comandos se corren desde la raíz de paceron-backend.

Antes de empezar (una sola vez)

1 Levantá el stack

make local-up

2 Levantá el backend contra la base local

go run ./cmd/api --stage=local

El --stage=local es obligatorio. Sin él el backend se conecta a Supabase y la demo va a modificar datos reales.

3 Verificá que el frontend apunte al backend local

En paceron-frontend, el .env tiene que tener:

EXPO_PUBLIC_API_URL=http://localhost:8080/api/v1

Y hay que reiniciar el dev server (npx expo start -c): Expo inyecta las variables al bundlear, no con hot reload.

4 Congelá el estado actual

make demo-baseline

Guarda la foto en backup/baseline.dump. Imprime el tamaño y un checksum para que quede registrado.

No lo hace nadie más por vos: la primera vez que lo corras es la que congela la foto de esta demo.

5 Comprobalo

make demo-status

Tiene que decir ✓ igual que el baseline. Si dice que difiere, no arranques la demo todavía: primero corré make demo-restore.

Entre rondas

Cuando una ronda termina y la siguiente va a empezar de cero:

make demo-restore

Vuelve a la foto en ~3 segundos. No reinicia contenedores, no toca el bucket, no pide reiniciar el backend.

Pide confirmación; para responder sin prompt: make demo-restore DEMO_FLAGS=--yes

Al terminar

1 Reset en frío — borra los volúmenes y vuelve a armar todo desde el baseline:

make demo-reset

Tarda ~15 segundos. Es la versión en frío: borra también el bucket de fotos, así que, a diferencia de demo-restore, no deja fotos que se subieron durante la demo.

2 Relanzá el backend — demo-reset recreó los contenedores:

go run ./cmd/api --stage=local

3 Comprobalo

make demo-verify

Tiene que decir ✓ la base está igual que el baseline.

Los comandos

  • make demo-baselineCongela el estado actual. Una vez, antes de empezar.
  • make demo-restoreVuelve al baseline. Rápido. Entre rondas.
  • make demo-resetVuelve al baseline. En frío: borra volúmenes. Antes y después.
  • make demo-verify¿La base está igual que el baseline? Sale con error si no.
  • make demo-statusEstado del baseline, contenedores, y si difiere.

Flags

  • DEMO_FLAGS=--yes — sin pedir confirmación. Ej.: make demo-restore DEMO_FLAGS=--yes
  • make demo-baseline-force — reemplaza el baseline. Solo si querés cambiar la foto a propósito.

Si algo sale mal

Lo que vesQué hacer
Postgres no responde make local-ps y make local-logs. Si no está levantado: make local-up.
Las fotos de perfil dan 404 Falta recrear el bucket: make demo-reset. demo-restore no lo hace y está bien que sea así.
El frontend no carga datos / error de red El backend no está con --stage=local, o el .env del frontend no apunta a localhost:8080. Recordá reiniciar el dev server.
"el baseline no coincide con su checksum" Se modificó o se corrompió. Si el cambio fue a propósito: make demo-baseline-force. Si no, recuperá el backup anterior.
"ya existe un baseline" Es a propósito: no se pisa solo. make demo-baseline-force si de verdad querés cambiar la foto.
Todo raro después de una ronda make demo-status primero. Si dice que difiere, make demo-restore.

Cosas que conviene saber

Ojo con dos cosas:

  • La base tiene datos reales — 34 usuarios con email, nombre y DNI. Es una demo interna, pero los datos son de personas reales: no los screenshots a la nada.
  • Si el backend se levanta sin --stage=local, escribe contra Supabase y la demo modifica la base de producción. Es el error más caro de todos los que hay acá.

Los participantes de la demo comparten la misma base. No hay aislamiento entre ellos: lo que toca uno, lo ven todos. Para varias rondas eso es justo lo que se quiere (cada ronda empieza del mismo estado), pero conviene que esté claro antes de empezar.

No uses make local-restore para esto. Elige el .dump más reciente de backup/, así que si alguien corre make local-dump durante la demo va a "restaurar" el estado roto y va a decir que salió bien.

La verificación mira cantidades de filas, no el contenido. Si una ronda sólo editó datos sin agregar ni borrar nada, demo-verify va a decir que todo bien. El restore sí los revierte igual.
